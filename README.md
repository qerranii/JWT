# JWT
**JWT (JSON Web Token)** — это современный «цифровой ключ» для доступа к защищённым ресурсам в интернете. Представьте, что вы приходите в гостиницу: при заселении (аутентификации) вам выдают электронную ключ-карту (токен), которая открывает только ваш номер (защищённые данные) определённое время.

Раньше сайты постоянно проверяли ваш логин и пароль при каждом действии (открытие письма, добавление товара в корзину). Это небезопасно (пароль могли перехватить) и медленно (сервер каждый раз сверял данные с базой).
JWT решает проблемы ввиде безопастности и скорости:
1. Вместо пароля вы получаете токен с ограниченным сроком жизни
2. Сервер проверяет токен самостоятельно, не обращаясь к базе данных.

Токен выглядит как длинная строка из трёх частей:
1. **Заголовок** - тип и алгоритм шифрования токена.
2. **Данные** - идентификатор пользователя, срок действия, права доступа и т.д.
3. **Подпись** - от кого был создан этот токен, гарантирует, что токен не подделан.
xxxxx.yyyyy.zzzzz
x - заголовок
y - данные
z - подпись

# Как работает на практике в веб-приложениях?
Вход в систему -> доступ к данным -> обновление токена -> выход
1. Вход в систему:
  Пользователь вводит логин и пароль → сервер проверяет их → создаёт два токена:
  Access Token (ключ) — для повседневных запросов, живёт 15-30 минут
  Refresh Token (ключ для продления) — живёт несколько дней, хранится в безопасном месте
  ```
  access_token = create_access_token(jwt_data)
  refresh_token = create_refresh_token(jwt_data)
  response.set_cookie(key="access_token", value=access_token, httponly=True)
  ```
2. Доступ к защищённым данным:
  С каждым запросом браузер автоматически отправляет access token → сервер проверяет его подпись и срок → если всё в порядке, возвращает запрошенные данные.

3. Обновление токенов:
  Когда access token «протухнет», клиент незаметно обменивает refresh token на новую пару. Пользователь продолжает работать без повторного ввода пароля.

4.  Выход из системы:
  При выходе токены удаляются, что сразу прекращает доступ:
  ```
  response.set_cookie(key="access_token", value="deleted", max_age=-1)
  ```

# Плюсы:
1. Безопасность
  1. Короткий срок жизни access token (15-30 минут) минимизирует риски при перехвате
  2. HttpOnly cookies защищают от XSS-атак
  3. Подпись токена гарантирует целостность данных
  3. Нет хранения сессий на сервере — меньше точек уязвимости

2. Производительность
  1. Не требует запросов к БД при каждой проверке токена
  2. Масштабируемость — серверы не делятся состоянием сессий
  3. Быстрая валидация — только криптографическая проверка подписи

3. Удобство разработки
  1. Самостоятельные токены содержат всю необходимую информацию  
  2. Простая интеграция между микросервисами 
  3. Кросс-доменная работа через CORS 
  4. Поддержка мобильных приложений

4. Пользовательский опыт
  1. Бесперебойная работа благодаря автоматическому обновлению токенов
  2. Не нужно повторно вводить пароль в течение нескольких дней
  3. Одновременная работа с нескольких устройств
